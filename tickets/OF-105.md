# OF-105 · Enforce valid order status transitions

| Type | Priority | Points | Reporter | Labels |
|------|----------|--------|----------|--------|
| Story 📘 | High | 3 | Product (Sam) | `domain`, `business-rules` |

## User Story
**As** the warehouse team, **I want** the system to reject impossible order status changes
**so that** shipped orders can't be accidentally reset and cancelled orders can't be shipped.

## Current behaviour
`PATCH /api/orders/2/status` with `{"status": "Pending"}` on a **Shipped** order → `200 OK` 😱

## Rules (agreed with Product)
```
Pending  → Paid, Cancelled
Paid     → Shipped, Cancelled
Shipped  → Delivered
Delivered → (terminal)
Cancelled → (terminal)
```
Setting the same status again (e.g. Paid → Paid) — **decide and document**: no-op or error?

## Acceptance Criteria
- [ ] Invalid transitions return **422** with a message like `Cannot change order status from Shipped to Pending.`
- [ ] Logic lives in `Order.ChangeStatus` (Domain), not in the controller or service
- [ ] Unit tests cover every allowed transition and at least 3 disallowed ones (hint: `[Theory]` + `[InlineData]`)
