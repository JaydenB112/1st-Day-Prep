# OF-115 · Add SKU to products + switch to EF Core migrations

| Type | Priority | Points | Labels |
|------|----------|--------|--------|
| Story 📘 | Medium | 3 | `ef-core`, `database`, `migrations` |

## Description
We use `EnsureCreated()`, which can't evolve an existing schema. Before adding columns we need real migrations.

## Acceptance Criteria
- [ ] Remove `EnsureCreated()`. Generate an `InitialCreate` migration and apply it with `Database.Migrate()` in dev
- [ ] Add `Sku` (string, required, max 32, **unique**) to `Product` in a second migration `AddProductSku`
- [ ] Existing rows get a backfilled SKU (e.g. `WID-0001`). Think about how to do this in the migration
- [ ] SKU exposed in DTOs and create/update requests
- [ ] Generate the SQL script for the DBA: `dotnet ef migrations script --idempotent`

<details><summary>Hints</summary>

```bash
dotnet tool install --global dotnet-ef
dotnet add src/OrderFlow.Api package Microsoft.EntityFrameworkCore.Design
dotnet ef migrations add InitialCreate -p src/OrderFlow.Infrastructure -s src/OrderFlow.Api -o Persistence/Migrations
```
Delete `orderflow.db` first. Why does adding a NOT NULL + UNIQUE column to a table with rows need care?
</details>
