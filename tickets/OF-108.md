# OF-108 · Validate create-customer requests

| Type | Priority | Points | Labels |
|------|----------|--------|--------|
| Story 📘 | Medium | 2 | `validation`, `api` |

## Description
We accept `{ "name": "", "email": "not-an-email" }` and save it. Garbage in, garbage forever.

## Acceptance Criteria
- [ ] Name required, 1–200 chars; Email required, valid format, max 320 chars
- [ ] Invalid requests return **400** with a ProblemDetails `errors` dictionary per field
- [ ] Same for `CreateProductRequest`: name required, price > 0, stock ≥ 0

<details><summary>Hints</summary>

Two common approaches. Know both, since teams have strong opinions:
1. **DataAnnotations** (`[Required]`, `[EmailAddress]`, `[Range]`): built in. `[ApiController]` auto-returns 400.
   On a positional record use `[property: Required]`.
2. **FluentValidation**: separate validator classes, more expressive, very common in enterprise codebases.
</details>
