# OF-107 · BUG: Duplicate customer email returns 500

| Type | Priority | Points | Labels |
|------|----------|--------|--------|
| Bug 🐞 | Medium | 2 | `error-handling`, `ef-core` |

## Description
`POST /api/customers` with an email that already exists blows up with a 500 (`DbUpdateException` / SQLite UNIQUE constraint).

## Acceptance Criteria
- [ ] Returns **409 Conflict** with message `A customer with email 'x' already exists.`
- [ ] Email comparison is case-insensitive (`Ada@Example.com` == `ada@example.com`)
- [ ] Discuss in PR: checking first (`AnyAsync`) vs catching the DB exception. What's the race condition with checking first? Why might you do both?

<details><summary>Hints</summary>

You'll probably want a new exception type (e.g. `ConflictException`) + a mapping in `GlobalExceptionHandler`.
</details>
