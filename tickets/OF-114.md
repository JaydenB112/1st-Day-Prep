# OF-114 · INCIDENT: /api/customers degrades under load

| Type | Priority | Points | Reporter | Labels |
|------|----------|--------|----------|--------|
| Incident 🔥 | **High** | 2 | SRE (on-call) | `performance`, `async`, `postmortem` |

## Description
During Black Friday load testing, p99 latency on `GET /api/customers` went from 60ms to 9s and other endpoints slowed down too.
Thread pool count climbed steadily. Dashboards attached (pretend 😄).

## Acceptance Criteria
- [ ] Find the root cause (hint: it's one line)
- [ ] Fix it so the call chain is async all the way from controller to repository
- [ ] Write a short postmortem in the PR: what happened, why it hurt *other* endpoints, how to prevent it (analyzer rule? code review checklist?)
- [ ] Stretch: prove it. Load test before/after with `bombardier`, `k6`, or `hey`:
      `hey -n 2000 -c 200 http://localhost:5287/api/customers`
